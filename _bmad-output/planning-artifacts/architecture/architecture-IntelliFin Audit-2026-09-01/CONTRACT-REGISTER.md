# Contract register — active Rust target

## 0. Authority and status

This register replaces the revision-5 contract inventory. Read it with [the active spine](ARCHITECTURE-SPINE.md) and accepted product design revision 3. It is the lean specification home for the shared boundaries below until implementation supplies executable schemas, examples and conformance tests. **Defined here does not mean implemented or tested.**

The `zobba-` namespace avoids silently reusing legacy wire contracts whose meaning has changed. Every row has one accountable owner; contributors cannot create an independent mutation or authority path. Follow AD-14 versioning for durable bytes and rolling compatibility. There is no requirement to preserve development data or implement old `v1` readers merely because those files exist.

The [archived register](archive/2026-09-30-pre-rust-rev5/CONTRACT-REGISTER.md) preserves all prior names and dispositions. Existing `docs/contracts/` files describe the legacy code until an implementation change retires them; none requires compiler-1/compiler-2, Builder, old queues or old schema in the target. Earlier NEW/EXTENDED/HOLDS promises and story placeholders are superseded by this register. No legacy application contract is edited in this planning consolidation.

## Legacy disposition by responsibility

| Legacy contract family | Target treatment |
|---|---|
| `executable-plan-v1/v2`, `promotion-v1`, compiler conditions, Builder authoring contracts | Retire as execution contracts. Reviewed assurance semantics become `zobba-assessment-v1` and `zobba-continuing-work-v1`; no replacement compiler. |
| `run-*`, `agent-execution-v1`, `agent-limits-recovery-v1`, `durable-escalation-v1`, `live-timeline-channel-v1` | Retire Run-specific envelope/state assumptions. Adapt useful idempotency, wait, recovery and event-delivery behaviours into Task/operation/projection contracts. |
| `tool-action-v1`, `agent-workspace-v1`, `workspace-capability-v1`, `credential-containment-v1`, `live-view-v1`, `replay-*` | Adapt guard and capability tests into Permissions, connection and computer contracts; replace browser-only/session and replay authority assumptions. |
| `evidence-package-*`, `capture-grounding-absence-v1`, `structural-snapshot-v1`, acquisition/derivation/input-quality/retention proposals | Adapt source identity, provenance, honest absence and integrity vectors into evidence/analysis/assessment contracts. Do not retain old ownership namespaces or mandatory legacy signing bytes. |
| `population-acquisition-v1`, `observation-registration-v1`, `adapter-extraction-v1`, `deterministic-evaluation-v1`, `run-level-gate-*`, `evaluation-review-sealing-v1` | Adapt meaningful quality/calculation fixtures; replace compiler-bound Observation/Run/Result gates with typed criterion/basis/evaluation and work-product review. |
| Proposed tenancy, engagement-task, connection/connector, disclosure/model policy, agent-loop, artifact/rendering/export contracts | Preserve useful intended guarantees through corresponding active rows; replace old Node/AI SDK/migration/one-task-chat and fixed model policies. |
| Proposed working-context/memory, skill and methodology-pack contracts | Replace universal approval/proposal hierarchies with ordinary Admin Save, exact bindings and automatically attributed scoped working knowledge. |

Implementation must record the exact adopted unit/fixture, source revision, destination, changes and applicable license/notices when reusing Codex or legacy units. Earlier file count/status totals are historical, not validation criteria for this fresh target.
