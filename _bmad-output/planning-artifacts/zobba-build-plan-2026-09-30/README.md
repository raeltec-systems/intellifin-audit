# Zobba implementation planning handoff

The accepted revision-3 design now has one active backlog: **9 epics and 55 stories**, with explicit dependencies and acceptance criteria. This package plans a brownfield cutover to the clean Rust product while preserving selected assets, fixtures and engineering lessons. It contains no application implementation.

- [Build sequence](BUILD-SEQUENCE.md) — recommended order, useful exits, early qualification, cutover and remaining commercial commitments.
- [First batch](FIRST-BATCH.md) — Stories **20.1–20.4**, ready for normal specification/build workflow as a bounded foundation.
- [Canonical epics and stories](../epics.md) — all story scope, non-goals, acceptance and validation.
- [Dependency graph](dependencies.json) and [requirement coverage](coverage.json) — machine-readable order, gate closures and planned FR/NFR/CAP/UX coverage.
- [Planning readiness](READINESS.md) — what was checked and what the result does not establish.
- [Active sprint status](../../implementation-artifacts/sprint-status.yaml) — the single queue consumed by installed `bmad-build`; new work remains backlog until the workflow advances it from evidence.
- [Historical backlog](legacy/epics-before-rev3.md) and [old sprint archive](../../implementation-artifacts/archive/pre-revision-3-2026-09-30/README.md) — superseded, not retroactively declared complete.

The first batch builds the workspace, scoped identity, durable commands and explicit conversation/Task cards. The first complete Task later requires methodology/skills/knowledge, native providers, real source/computer/private sign-in, isolated analysis, evidence, typed evaluation and human review. The recurring baseline adds a later Check occurrence. Accepted speech/helpers/integration breadth and operational qualification complete the declared release scope; later contact channels and proactive discovery remain separately qualified extensions.

The remaining owner commitments are customer applications/authentication and service envelope; region/processing/retention terms; and pricing/allowances/Windows entitlement. The [operating budget](../zobba-operating-budget-2026-09-30/OPERATING-BUDGET.md) records assumptions. Recommended defaults are named Linux/browser profiles with measured concurrency, a US East pilot subject to accepted residency/processing and retention terms, and a platform fee plus pooled metered usage with explicit caps and separate Windows pricing. These gate customer commitments, not the first local implementation batch.
