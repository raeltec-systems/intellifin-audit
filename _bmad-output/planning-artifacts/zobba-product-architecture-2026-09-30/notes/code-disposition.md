# Current-code disposition for the Zobba product design

Evidence checked 30 September 2026. Repository `/workspace/intellifin-audit` is clean at `9c17d19e84d3df3e5da48a48ac494b8071696e9b`. A read-only `git ls-remote origin HEAD refs/heads/main` returned that same revision for both. Latest merge is PR #67, Story 10.12: Epic 10 owner items. No repository changes, deployment, or tests were performed for this design review. Prior setup/test reports are historical evidence, not fresh results of this inspection.

## Recommendation

Build a fresh Rust application backend and agent runtime against a new development schema. Retain PostgreSQL and object storage as technologies, the Pair design assets, and the best behavior specifications and synthetic fixtures. Port useful mechanisms deliberately. Remove compiler-1, its Builder, and its orchestration from the active product. Do not introduce compiler-2 alongside it or keep a TypeScript service alive solely to execute development-era Runs. Preserve selected research and golden vectors in an archive/example package. This is a design recommendation; no destructive reset is authorized or performed here.

The current code is a mature implementation of a different product unit. `audit_run` requires a Procedure and Procedure Version (`packages/infrastructure/src/db/schema.ts:801`, especially 805–806). The template vocabulary is hard-coded to P-1..P-4 (`schema.ts:551`) and explanations explicitly forbid runtime template editing (562–565). The model returns bounded JSON proposals for actions/evaluation, rather than owning a continuing objective (`packages/infrastructure/src/runs/agent-model-gateway.ts:95`). A clean task/operation/artifact/engagement schema avoids spreading nullable Procedure fields and compatibility modes throughout the new runtime.
