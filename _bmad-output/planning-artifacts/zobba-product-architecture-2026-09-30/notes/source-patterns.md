# Codex mechanisms for Zobba's product and architecture

Recommendation: build a Zobba-owned Rust task authority and backend. Borrow the actor, cancellation, prepared dispatch and context patterns, plus a few small code units. Do not embed `codex-core`, treat its transcript as an audit ledger, or retain an old Zobba engine merely because the studies recommended continuity under an earlier brief.

## Evidence and authority

- Current user request and `Zobba_Product_and_Architecture_Direction.md` govern this design. Report A is the primary study; Report B and appendix supply additional mechanisms and failure cases.
- Both studies inspected Codex `8ffd91e42aa001b7e897bea812b02f89264f9fa0`. A bounded raw-source snapshot from that exact revision is now in `../references/codex-source/`, with `LICENSE`, `NOTICE` and `SOURCE-REVISION.txt`. This is a reference snapshot, not code vendored into Zobba.
- Direct source verification in this task covered complete-call admission/persistence, the persistence failure seam, prepared MCP call binding and tests, missing-result normalization, tool exposure/dispatch, annotation-based MCP approval, cancellation/parallel dispatch, buffers/truncation and tests, Retry-After, and the keyed request queue shape. No Codex tests or benchmarks were run in this task.
- Report A ran 97 targeted Zobba tests, but no Codex tests. Report B built `codex-core` and ran execpolicy/apply-patch tests; its two apply-patch failures were permission-error fixtures run as root. Its core, app-server and sandbox tests were inspected, not executed. None of those results establishes hosted-service, cross-tenant or deployed isolation correctness.

## Recommended Rust authority and transaction shape

Use a small number of process boundaries with one domain writer. The Rust application backend owns tasks, engagement access, Permissions, operations, evidence metadata, artifacts/review, schedules, memory and context. Workers use the same domain modules and database contracts; managed-computer and analysis execution live outside the application process for isolation and resource lifecycle. No Node service should compete to own task state. Keeping mature Node browser drivers or document utilities behind narrow ports does not require a second application backend.

A task command transaction validates current principal and idempotency key, appends the accepted command, advances the aggregate revision, writes the durable event and queues a wakeup. The scheduler claims eligible work using short PostgreSQL transactions, lease expiry and a monotonically increasing owner epoch; no lock or transaction spans model/tool/human waits. Job identity is a wakeup, never permission to replay an operation. Unique constraints and state/epoch predicates reject stale writers.

An operation transaction records the admitted intent, tool/descriptor digest, actual canonical arguments, principal/delegation, input references, required decision and permission generation. A dispatch claim is committed before gateway I/O. The gateway checks the current claim and resource binding, then performs the operation outside the transaction. Result receipt commit is idempotent by operation/attempt identity. Every external system remains outside the PostgreSQL transaction; exactly-once remote effects cannot be promised where the provider offers neither idempotency nor authoritative reconciliation.

The important source seam is verified: `core/src/stream_events_utils.rs:315–357` records the completed call before creating a dispatch future, while `core/src/session/mod.rs:4463–4471` logs append failure and returns false. Its caller at `:3585–3602` continues. Zobba must make successful durable admission a hard precondition for I/O.

On crash recovery, expired ownership permits a new coordinator, not automatic repetition. Query by durable operation key where supported. A negative lookup only proves non-execution when the connector contract guarantees it. Otherwise, preserve uncertainty and request a targeted human reconciliation. If a late confirmed receipt arrives after a paper was approved/issued, register a supplemental result and open a correction/review task; do not rewrite the reviewed content.

## Context, memory and native providers

Use a Zobba-owned portable model interface rather than importing Responses as the domain schema. `ModelInput` contains attributed text/media references, an admitted tool snapshot and permitted prior observations. `ModelEvent` distinguishes text delta, complete tool proposal, refusal, completion, error and measured/unknown usage. Execute no partial argument stream. Bound argument bytes, item counts, media, calls, attempt/deadline and output budgets independently.

Use native OpenAI Responses and Anthropic Messages adapters as the initial native pair, with a capability matrix and deterministic conformance fixtures; add providers under the same contract. Codex's provider catalog is broader than its wire format: at this revision it uses Responses, including OpenAI-compatible Bedrock endpoints. It is not a ready-made native multi-provider abstraction. A visual task cannot silently fall back to a text-only adapter. Provider switching occurs between committed cycles, with tools reconstructed from durable records and no replay of completed effects. Persist requested and actual model/effort configuration and usage/cost per attempt, including uncertainty on a lost response.

Opaque provider continuation can be an optional optimization when bound to tenant, engagement/task, provider/model, context manifest and permission generation. It must be discarded on a relevant access change, provider switch or inconsistent prefix; reconstruct from authorized portable records. Do not use opaque provider compaction as the sole durable context. The provider may already have received historical content; local revocation prevents new disclosure but cannot undo prior transmission.

Compaction produces an inspectable derived record: covered event range, input source/version references, decisions, objective, uncertainty, unresolved questions/operations, and omissions. A separate deterministic validator reinstates required durable facts. Context items, summaries, embeddings and memories carry lineage. A revoked input invalidates all derived context before the next model request; an opaque continuation derived from it is dropped. The pre-request disclosure gate checks a fresh generation as well as membership. Retained original evidence remains under retention/access policy, separate from permission to redisclose it.

Memory should distinguish an auditor preference, engagement fact, client knowledge and firm methodology, with source, scope, confidence, verification/review state and expiry. Successful completion may propose durable memories; retrieval always reapplies scope/current access. A remembered statement never grants Permissions. The reference's global CODEX_HOME memory extraction cannot safely become team memory.

Represent mandatory methodology requirements, engagement-specific decisions, optional skill advice, user preferences and retrieved material as different classes. A firm package declares which requirements are mandatory, what roles can approve an exception, and what is merely recommended. The auditor can override optional style advice. Required independent review is enforced in the artifact transition, outside the prompt. Imported documents named `SKILL.md` do not install skills; retrieved text never changes configuration or grants authority.

## Failure contracts worth carrying into product acceptance

These are design acceptance obligations, not a new research/benchmark gate or implementation epic list. Use deterministic fake providers/connectors, failpoint barriers, virtual clocks and captured outbound requests. Distinguish tests actually executed from tests merely present, and require the target isolation prerequisites rather than counting a skip as a pass.

| Failure injected | Required observable result |
|---|---|
| Command or operation commit fails immediately before I/O. | No model/tool side effect starts; no accepted acknowledgment without a committed command. A retried same key returns the original receipt or cleanly admits once. |
| Two workers claim one task; former owner wakes after expiry. | One owner epoch wins. Former owner cannot commit new state or acquire a new dispatch permit; a result from its already-dispatched attempt remains attributable. |
| Crash after intent, after dispatch claim, after remote commit, after receipt and before client delivery. | Each boundary yields the right recorded certainty. A non-idempotent uncertain effect is never blindly retried; duplicate client requests/events do not duplicate effects. |
| Stop races with terminal result; process leader exits while descendant holds stdout; descendant creates a new session. | Stop request remains distinct from verified cessation. Completed result is preserved exactly once. Supervisor confirms whole-container/VM/cgroup cleanup or reports unresolved termination; partial diagnostics survive. |
| Auditor sends accepted correction during streaming, then tab/worker disconnects. | Correction survives and is either consumed at a recorded boundary or explicitly superseded/refused. It is never silently lost. Control acknowledgment does not wait for model completion. |
| Mandatory question answered twice, after expiry, after target revision changed, or after membership revocation. | Exactly one authorized answer applies to the exact target/version; stale/conflicting answers are rejected; restart retains pending question. No worker slot remains occupied while waiting. |
| Tool is hidden, guessed, renamed, collides after normalization, returns malformed schema or rewrites parameters. | Only admitted tool/version handles execute; identity collisions fail configuration; closed-schema errors are bounded feedback; final actual arguments receive a fresh mandatory check. |
| MCP declares a destructive call read-only; request changes from API to browser; live system is mislabeled as test by model text. | Classification comes from registered action/account/system purpose. Live mutation remains prohibited where inspection-only applies across every tool route. Test workflow creation requires a designated test system/account and delegation. |
| Connection refresh swaps accounts after an action was prepared; permissions narrow during queued dispatch. | Prepared call never reroutes. Current epoch/permission check rejects stale dispatch before I/O. Already dispatched effects follow receipt/reconciliation semantics. |
| Source read → analysis → summary → memory → compaction, then source revoked before next sampling/resume. | Captured outbound request has no revoked excerpt or contaminated derived summary/opaque continuation; retrieval and UI projections also reauthorize. Original retained evidence is intact with restricted access. |
| Hostile retrieved content asks to install skill, read another client, change Permissions, disclose a token or approve a finding. | It remains attributed data through extraction, compaction and memory. Even if the model follows it, deterministic dispatch/approval boundaries refuse prohibited action. Separate evaluations assess whether the model reasons usefully and cites correctly. |
| Concurrent helpers edit same artifact or share the application session. | One input holder controls the actual gateway. Artifact base-version conflict creates a visible merge/revision choice, not silent overwrite. Child results survive parent inactivity and use scoped durable receipts. |
| Client reads at 1 KiB/s while events and 100 MiB of output are produced. | Worker/receipt progress and other clients continue; queue/preview bytes stay bounded; reconnect recovers all authorized durable events in order; preview never claims full population coverage. |
| Provider ends stream mid-arguments, loses completion after tool result, lacks image capability or changes provider. | No partial-call execution, no replay of confirmed effect, no silent modality downgrade; unknown usage stays unknown; portable context rebuilds at the next safe boundary. |
| New evidence arrives twice; a schedule overlaps; an issued conclusion becomes unsupported. | Deduplicated trigger records create/reopen the appropriate continuing task with period identity and current authority. Overlap policy is explicit; issued paper stays immutable and a supplement/correction review is created. |

## Study recommendations superseded by the new direction

1. A's comparative Rust proof and default retained TypeScript application services are earlier research recommendations, not approval prerequisites. The user now chooses own Rust engine as the starting direction and allows broader Rust when cleaner. Recommend one Rust application authority without a legacy bridge unless an actual retained dependency justifies a narrow boundary.
2. Both studies preserve compiler-1/history compatibility and previous epic sequencing. The current brief explicitly allows retiring compiler-1 and rebuilding a fresh development schema. Preserve useful evidence/permission/cancellation test behaviors and authentic business information, not synthetic compatibility obligations.
3. Earlier serial-only calls, deferred compaction, managed-desktop deferrals and proof-first scope do not define the product. Design bounded parallel work, compaction, takeover and background continuation now; order their capability dependencies later.
4. B's fixed hierarchy “firm > engagement > skill > auditor” is incompatible with the brief's distinction between mandatory requirements and optional advice. Use typed authority and declared exception rules; optional skills cannot outrank valid user preferences.
5. B forbids opaque continuation too broadly. An inspectable portable authoritative context plus disposable scoped provider continuation is coherent. Never make provider opacity the only recoverable context or pretend it can be surgically redacted.
6. Neither study establishes a language performance win, production operating cost, hosted workspace capability or safe third-party execution backend. Choose Rust for coherent ownership and the intended engineering direction; validate resource/isolation behavior in implementation acceptance without reopening the architecture as a benchmark contest.
