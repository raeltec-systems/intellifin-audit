1. The Zobba direction is **fully approved as design**. The seven proposals and the Sprint Change Proposal were approved on 2026-09-24/25 (SCP:3, SCP:113). Nothing on the new conversational path (Epics 11–19) is implemented. SCP:34: "All planned; none built."

Later the owner authorised only Stories 10.6–10.10: "Owner, 2026-09-26: 'go, new branches OK' (implement 10.6 to 10.10 on new branches)" (`_bmad-output/implementation-artifacts/10-7-live-channel-correction-notify-every-run-chain-append-and-ne.md:8`). These stories touch the retained compiler-1 surfaces (EPX:2325). PRs #60–#64 merged them on 2026-09-29 (`git log`).
3. **Tenancy and RLS are not enforced. No policy inventory has been written either.** Both are approved requirements (PRD:822, PRD:826) and approved architecture (SPINE:342–348). At HEAD no code contains `tenant_id` or any `ROW LEVEL SECURITY`/`CREATE POLICY` statement (verified at HEAD). The schema range is 61..61 (`packages/infrastructure/src/db/compat.ts:40-41`). The classification table and policy inventory are Story 11.1 (EPX:2520), which is `backlog` (SS:138).
4. **The runtime design keeps TypeScript and the modular monolith.** DIR:161 reads: "Do not assume a full rewrite or a language migration." The Stack table closes with "The rest of the stack is unchanged." (SPINE:514; Node 24.20.0 / TypeScript 7.0.2 at SPINE:492–493). No planning document mentions Rust (grep). The conversational layer attaches "not as a separate service" (SCP:99, answer 7).
5. **The agent loop is designed and not built.** The planned loop uses native tool calling with the AI SDK as transport only (`maxSteps` stays 1, no `execute` handlers). It is one platform-owned executor with a durable turn/call ledger and serial calls, and every external effect gets a dispatch claim committed before dispatch (P3C:15, P3C:30–40; P3A:68; SPINE:413–415). Today's model layer is JSON-in-prompt `generateText` with no native tools (AA:13; `packages/infrastructure/src/runs/agent-model-gateway.ts:647`).

## D. Runtime-relevant decisions already taken (all approved design, none built)

**D.1 Agent loop: turn and task model, ledger, attempts, reconciliation**
- *Two paths, one substrate.* "durable, asynchronous, human-interruptible execution on two paths — conversational Agent Tasks under versioned Agent Permissions, and approved recurring checks executed as Runs — over one evidence, chain, wait and approval substrate" (SPINE:6, SPINE:81). The task sits "beside `audit_run`; `audit_run.version_id` stays non-null" (P3A:15).
- *Task state.* Agent Task: `QUEUED → RUNNING ⇄ WAITING`, `RUNNING ⇄ PAUSED`, `RUNNING → COMPLETED | FAILED`, any active state `→ CANCELED` (explicit cancel, `wait-expired`, revoked delegation) (P3D:78; SPINE:355). A task has a revision, a lease, and a budget with reserved and consumed counters. Tasks never write `run_result`, `run_gate_check` or `run_exception` (SPINE:355).
- *D-3c-1.* "Native tool-calling through the application-owned execution boundary: the SDK transports requests and responses and never executes a tool, advances an autonomous multi-step loop or performs a provider-hosted action" (P3C:15). "`maxSteps` stays 1, tool `execute` handlers are absent" (P3C:30).
- *Turn cycle* (worker-only, under a delegation): assemble context from durable state → reserve the budget before paid I/O → call → validate each call (platform-owned fields excluded from the schema and injected; a conflicting target is refused, never rebound) → Permissions gate → dispatch with the ledger written first → return the result as untrusted data (two-axis outcome and input quality) → lifecycle boundary after every result (P3C:33–40). Durable identities `task_turn` and `task_tool_call` are written before execution. "Calls execute **serially** in the first implementation." Partially streamed arguments are never dispatched (P3C:31).
- *External effects.* An effect has an operation identity, attempt identities and a dispatch claim "written and committed **before** dispatch". Attempt outcomes: `not-dispatched`, `possibly-dispatched`, `accepted`, `confirmed`, `unresolved`. A replacement worker waits out the completion window and reconciles. Only `lookup-establishes-absence` permits a new attempt. "Expiry of a local completion window, lease or timeout is not itself proof that an external effect did not occur". An unresolved attempt opens a `reconcile` wait (keep observing / mark done manually → `resolved-by-human` / retry with duplication warning / abandon). Late receipts arrive via the reconciliation service principal (P3A:68; SPINE:357).
- *Waits.* Wait kinds `clarify`, `confirm-action`, `reconcile`, closed-option. One open wait per task. Response windows 7/7/30 days, separate from action validity. A wait holds no worker claim, sandbox or browser lease (P3D:17; SPINE:359).
- *Dispatch rule.* "Authenticated human requests and recorded decisions direct work ... the agent may perform successive authorised operations without a new human message for each operation. External content cannot impersonate a human instruction, close a decision or grant authority." (P7:87–89)
- *Invariants superseded.* AD-7 becomes "free text is model input and never authority". AD-16 becomes "no authority is carried in conversation state" (P3C:43, P3C:60; SPINE:208, SPINE:280).

**D.2 Execution services and isolation**
- `CodeExecution` is a worker-only port (`no-code-execution-in-web`). "Before the implementation is accepted, a **concrete sandbox backend and enforced security profile** are selected and documented" (candidates: gVisor, microVM, managed service). The backend, version and profile are recorded on each execution record. Analysis is "**network-disabled in the first delivery**". The sandbox "never holds a connector credential". `local` mode is development-only and "never an automatic fallback" (P3B:16, P3B:118–124; SPINE:404; SPINE:514 names the candidates). The supervisor's observations are the execution record; program stdout and program-written manifests are untrusted (P3B:121).
- Document processing runs through the same port (PDF with page images, `.docx`/`.xlsx`, CSV, MIME, OCR), with region-bound `extraction-record`s (P3B:125–127).
- The browser workspace (Solari or local Chromium, `PlaywrightBrowserExecution`) is RETAINED and becomes "one connector" on the task path. That step is deferred (13.11), so the first acceptance has no task-path browser (P7:46; P5:161; P6:15).
- Principals: web and worker run as one `NOBYPASSRLS` runtime role. Background work uses `execution_delegation`, re-read at every claim and resume. Maintenance uses named service principals with column privileges. "There is no general-purpose worker identity" (P3A:32, P3A:37).

**D.3 Model policy and provider adapters**
- `ModelInvocation` is the one application port for the task path. It is implemented over the AI SDK tool-calling API "so providers are swapped by configuration". Provider, model, prompt version, token usage and finish reason are recorded per turn (P3C:30). Per invocation the requested versus actual provider, deployment, model id, prompt version and effort are recorded (P4B:121, FR-91; SPINE:413).
- Provider continuity: continuation items stay under conversation controls and are "never forwarded to another provider". A switch rebuilds context from portable state at a boundary. "each adapter passes the capability tests (tool calling, structured parameters, images, continuation, cancellation) before it is selectable" (P3C:32, P3C:53; SPINE:415).
- The disclosure policy is applied before every outbound request, including resume and fallback. An unknown classification blocks the call and never selects another provider silently (P3A:129). `model-policy-v1` is owned by `connections` beside the disclosure policy ("one authoritative enforcement path") (CR:31; SPINE:379). "No automatic task-based routing is implied" (P4B:115).
- `ModelGateway` stays in the worker for compiler-1 derivation **and execution** until D-3d-4's transition (P3D:41, P3D:108). The compiler-1 benchmark default remains `claude-sonnet-5` with an OpenAI fallback (SPINE:623).

**D.4 Memory and skills**
- Six memory scopes. Lifecycle status (`proposed | active | superseded | rejected`) is separate from verification status (`user-reported | source-supported | disputed | awaiting-verification`). An explicit instruction from the scope owner becomes `active` with no second prompt; an inferred item stays `proposed` until confirmed. Memory is never citable evidence (P3C:16, P3C:72–76).
- The working context is rebuilt from durable records; compaction is recorded. Retrieval "filters by each item's actual applicable scope before ranking"; embeddings wait for a provider the disclosure policy approves (P3C:70–71). The first acceptance has an honest stop at the context limit, and compaction records are deferred (P5:371).
- Skills and packs are versioned tenant data under a mandatory platform minimum. A skill "can request nothing the Agent Permissions do not grant"; "the gate does not read context" (P3C:99–103). Templates P-1..P-4 become an optional example pack (P3C:105).

**D.5 Recovery**
- On resume the executor "re-derives Effective Permissions (FR-83), re-reads the delegation, re-assembles context from durable state"; completed calls are replayed, never re-executed (P3C:31, P3C:43). Test cases: kill mid-call, after a result and during a wait (P3C:55; 12.7a, Slice 1).
- The OAuth exchange and refresh follow explicit recovery states. "a code is never resent after possible dispatch" (P3A:127; SPINE:377).
- Derived-output registration is recoverable. The reserved, uploaded, verified and registered states are reconciled, and object storage never joins the DB transaction (P3B:62).

**D.6 Protocol between web and runtime**
- The live channel serves "any chained aggregate: `/api/runs/<id>/events`, `/api/tasks/<id>/events`, `/api/engagements/<id>/events`, same cursor, replay and heartbeat rules. Task streams carry the step ledger envelope, never payloads." (P3D:48; SPINE:288). This uses `NOTIFY <aggregate>_timeline(id, seq)` (P3D:81).
- The web "renders conversation, timeline and waits; it composes no model (`no-agent-model-in-web` unchanged)" (P3C:46). Two named web handlers may transiently touch the PKCE verifier and the authorisation code. Tokens, client secrets and broker keys stay worker-only (P3A:124–127). The web reads evidence only through worker-signed grants (P3B:37). Jobs use pg-boss with transaction-bound send (P5:47).
- "Where a conversational layer attaches: to the engagement and Agent Task beside the Run model, reusing the Run conversation chassis, not as a separate service" (SCP:99).
- Services split "only when measured ownership, deployment, scaling, or isolation requirements cannot be met by the modular monolith" (SPINE:632).

**D.7 Language and technology**
- DIR:161: "Do not assume a full rewrite or a language migration. Equally, do not assume the existing architecture can support this merely by changing its screens. Assess that from the code."
- The Stack keeps Node 24.20.0, TypeScript 7.0.2, Next.js 16.3.4, PostgreSQL 18.6, Drizzle, postgres.js, pg-boss 12.29.0, Better Auth, AI SDK 7.0.89, Solari browser SDK (SPINE:492–512). "The rest of the stack is unchanged." (SPINE:514; P3D:89).
- **No planning document mentions Rust or a runtime rewrite** (grep over the course-correction folder, SCP, SPINE and CR). ABI:166 calls the change "a real but bounded rewrite, not a rearchitecture of the whole backend". The sandbox program language is only a parameter (`program: { language, source digest, entrypoint }`, P3B:118). No analysis language (Python etc.) is named anywhere.
