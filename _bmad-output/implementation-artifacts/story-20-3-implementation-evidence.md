## Delivered behavior

Task commands now persist one immutable Received receipt together with state, scoped commit-ordered events, and a durable wakeup. Parsed command meaning binds author, composite scope, kind, exact target Task/cycle, and retained text; retry reauthorizes and returns the original receipt, while changed meaning conflicts. Applied is a separate event. Create, Guide, Pause, Resume, Stop, and Continue remain explicit.

Migration `0003_tasks.sql` adds the scoped Task authority and exact-attempt observation store. Existing migrations 1/2 and catalogs 1/2 bytes remain unchanged. Startup validates the exact 512-line PostgreSQL 18 catalog and narrow runtime grants; migration remains an explicit CLI action. Every task transaction uses exact current membership and forced RLS. Discovery exposes only content-free routing columns with explicit column SELECT grants. Separate `task_deliveries` rows permit dispatcher lease updates without permission to change Task scheduling, routing, or authority.

The independent API reserves two database connections and four concurrent requests for Guide/Pause/Stop, including fresh session authentication and exact Origin/CSRF verification. Ordinary Task traffic has eight concurrent requests and shares the existing four-connection pool. Bodies are limited to 32 KiB, content to 4000 UTF-8 bytes, and requests to 6 seconds. Task/command IDs and keys remain bounded ASCII identities; authors come from server sessions. Task pages expose at most 100 records plus an explicit continuation cursor; direct selection is independent of list pages. Event pages are 100 records with decimal-string cursors; counters exposed to browsers are strings.

Each engagement admits at most 100 open Tasks. Continue must reacquire capacity; paused Tasks already count. An indexed monotonic application cursor applies at most 32 new commands per boundary, without rescanning retained command/event history. An open-Task partial index bounds admission independently of retained stopped Tasks. The worker has at most 4 child runners and 4 database connections, polls every 200 ms, and discovers at most 8 routes per query (the coordinator requests only available child capacity). Database-time Task owner leases and delivery leases are 5 seconds; released deliveries wait 1 second and use oldest-delivery ordering so unavailable older Tasks cannot repeatedly hide untouched work. Inert duration defaults to 500 ms and is bounded 10–30000 ms; the child has an empty environment and no output, model, tool, computer, or audit behavior.

All worker database ports have a 2-second client deadline; startup connection is bounded to 7 seconds. Child exit, shutdown, and the 31-second cancellation deadline are observed concurrently with 200 ms authority polling. Cancellation joins are bounded to 2 seconds, and worker shutdown to 20 seconds; an unconfirmed join remains uncertain. Coordinator termination or panic withdraws readiness. Worker diagnostics use fixed codes, emitted at most once per code per 5 seconds, without identifiers, capabilities, content, or raw errors. Shared delivery and execution meanings live in the domain, ports in the application, and SQL adapters in infrastructure.

## Lifecycle and limits for Story 20.4

- `state=paused` or `state=stopped` records accepted desired control. The separate cessation value must drive whether the view says pending cessation, confirmed cessation, or reconciliation required. Never render bare confirmed Paused/Stopped while cessation is pending.
- A successful inert child exit is an immutable `completed` **observation**, followed by Task `Waiting/Confirmed`. It does not complete an objective or imply model understanding, audit success, or external effects. Guide retains exact plain text; it does not implicitly restart a paused, stopped, or already waiting Task.
- Resume explicitly retains the paused cycle. Continue explicitly creates a new cycle after confirmed Stop. New controls naming the old cycle refuse; an identical retry can still return its original historical receipt after current authorization.
- The accountable human and recorded background execution actor are the Create author. Worker IDs, owner epochs, execution epochs, intent revisions, and Task revisions are separate. Another current member can issue scoped controls without silently taking over background authority. Reassignment is a later capability.
- Revocation blocks protected reads, claims, and transitions. A tracked local child is cancelled without rereading revoked work; only an exact capability can submit its bounded immutable observation. A newly authorized coordinator can incorporate those observations after recorded execution authority is restored.
- Consumed claims are the possible-dispatch cutoff. Abrupt process loss, a lost consumption acknowledgement, local runner loss, or inability to join a child leaves reconciliation required; expiry never proves quiescence, and replacement owners never blindly replay it. Other Tasks and controls stay available.
- The worker retries the same immutable observation up to 5 times with 500 ms backoff for database unavailability. If all writes fail, its local fact/capability is lost on runner exit; durable consumed activity remains uncertain. This foundation deliberately does not invent an external reconciler or claim success from process absence.
