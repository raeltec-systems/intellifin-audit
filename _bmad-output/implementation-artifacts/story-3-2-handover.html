Population acquisition

Story 3.2 gives a Run a preserved, checked population before it evaluates any records.

Ready for review · Paused after Story 3.2

The practical change

For an approved adapter-only Procedure, starting a Run now invokes a worker stage that reads the frozen CSV or supported JSON API source, saves its original bytes, checks its independent declaration, and records which rows belong in the population.

A complete population waits for Target checks. A bad count, digest, schema, or required inclusion value produces an explicit diagnostic. Missing evidence cannot produce a Pass.

What you can inspect

  • The Run page shows acquired, included, excluded, and indeterminate row counts.
  • Exclusions and invalid values have reasons, with pagination for longer lists.
  • Evidence has a stable identity and the SHA-256 digest of the preserved source bytes.
  • The worker records attempts and progress so a restart can resume safely.

Decisions that matter

  • Execute the source frozen at approval. A later binding edit cannot substitute another source.
  • Apply the requested Run period without rewriting the approved plan.
  • Keep money as exact decimal strings. USD 100,000 is included; other currencies are excluded without conversion.
  • Keep invalid inclusion values visible as indeterminate. They are not ordinary exclusions.
  • Record expected digests before upload; verify stored bytes before registering Evidence.
