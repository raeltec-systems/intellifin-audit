## Owner, activation and callback trace

1. App refresh binds the current session and engagement reads; replacement calls `withdrawReplacedKnowledgeSession` before rendering ready state (`App.tsx:115–145`). Actual engagement denial discards that scope's custody; identity/session refusal and sign-out discard the appropriate broader custody (`:134–162`, `:173–182`, `:211–222`). Transient transport failure instead unmounts into the interruption view without deleting knowledge memory.
2. `ConversationWorkspace` passes projection readiness to the private preference and selected Task knowledge owners. Task components are keyed by exact actor/session/Task, and the selected working-context subtree is keyed by Task/opening. Methodology/skills context callbacks report only their currently verified owner projections; Task knowledge additionally requires exact Task ID/epoch and matching methodology binding before rendering its knowledge fragment (`TaskKnowledge.tsx:88–94`).
3. `useSkillInspection` updates the activation generation during render when owner or readiness changes. It discloses only state matching that owner/generation. Cancellation clears request ownership before aborting; successful and failing continuations check the current request, owner and activation. Thus an intentionally cancelled stale failure cannot invoke a current source-denial callback, and an old success cannot authorize a reactivation (`useSkillInspection.ts:12–47`).
4. Knowledge reads perform exact query/record/status/Task-epoch/method-binding verification plus a bound current-session postcheck before they become inspection state (`knowledge.ts` read/verify helpers). Original source preview uses original-scope evidence reads and identity equality; Guide source uses its original Task/scope. Neither borrows the destination scope.
5. Source denial deliberately changes only the protected knowledge fragment generation and clears its editor. Custody patches preserve pending requests, including unrelated accepted-but-unconfirmed destination commands. The new fragment must independently succeed before those recovery controls are shown again. The exact inspector is a child of the withdrawn page, so its target/value/preview cannot remain rendered independently of that page.
6. Source-correction status initialization is separately fenced by draft activation, predecessor identity, verified read and the latest draft ref. It merges only `expected_source_revision` into the current form, preserving edits made while the read was in flight (`TaskKnowledge.tsx:124–133`). The held-status browser journey at `knowledge.spec.ts:284` checks that exact behavior.
