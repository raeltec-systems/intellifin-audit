## Limits and next consumer

Selection is attributable context, not execution. `current_use` is a fresh standalone inspection, not a cached authorization token or transaction-local invocation gate. Later invocation must compose current skill eligibility at its actual admission/consumption boundary and pass existing exact-operation checks.

Storage limits are 128 versions/2 MiB stored installation commands per organisation and 128 selections/1 MiB receipt JSON per Task. Full bindings lower practical selection count. Each policy need has 256-region/65,536-comparison bounds; a scoped inspection shares 1,048,576 comparisons. Exhaustion reports unavailable while retaining metadata/history. Exact requested-version selection/use receives a fresh bounded assessment. Status restriction and exact recovery remain available at admission capacity.

Skill responses have an 8 MiB browser limit; ordinary reads remain 4 MiB. The maximal conservative discovery envelope is 7,467,743 bytes, including the longest redacted bound shape and status provenance. Assignment/history/impact reads use 50-item pages. Draft custody is limited to 16 exact audiences/8 MiB and is never browser-persisted or auto-submitted.
