## Remaining verification gap

### VG-4 — Explicit assignment removal does not verify which live execution scopes are fenced

- **Changed surface:** The B07 repair adds a separate `assignment_mode='remove'` scope-selection branch in `membership_fence`, `zobba/migrations/0005_membership_administration.sql:150`. That branch must fence selected removals while preserving execution in the target member's other engagements; the subsequent assignment update at `:222` is independent of that selection.
- **Impacted consumer or site:** The large-membership editor submits Remove mode at `zobba/web/src/MembershipWorkspace.tsx:158`. Its Save reaches `membership_write` and the fence at `zobba/migrations/0005_membership_administration.sql:220`; the selected scopes control Task epoch/state changes, admitted Task/operation claim abandonment, and delegation revocation at `:155`, `:163`, `:164`, and `:175`.
- **Existing test evidence:** `Regression gap`: `zobba/crates/infrastructure/tests/membership/legacy_upgrade.rs:234` checks the resulting version, count, completeness, removed assignment and retained off-page assignment. `zobba/crates/api/tests/membership_http.rs:1001` checks successful Remove and assignment counts/completeness. `zobba/web/tests/browser/membership.spec.ts:434` checks durable selected assignment removal across pages. None of these tests sets up and asserts live execution in both the removed and preserved scopes. The real Task/operation/delegation revocation tests use the Replace-mode helper at `zobba/crates/infrastructure/tests/membership/revocation.rs:31`, including repaired VG-1. Whole-repository symbol/import-reference searches for `AssignmentMode::Remove`, `assignment_mode`, `membership_fence`, `LegacyAssignmentFields`, `legacy_assignment_pages`, and `legacy_upgrade` located those mode tests plus contract/adapter definitions; no additional Remove-mode execution assertions were found.
- **Missing verification:** A Remove-mode Save with unchanged roles, active status, and membership expiry must advance/fence execution and revoke delegation only in explicitly removed engagements. A live Task, admitted claim, and delegation in an unselected engagement must remain unchanged.
- **Demonstration:** Replace the Remove branch's selected-assignment predicate with `a.active`. The independent assignment UPDATE would still remove exactly the selected rows, so the existing page/count/assignment assertions would pass, but the fence would pause Tasks, abandon claims, and revoke delegation in every active assignment held by that member. Conversely, making that branch false would leave the selected scope's durable execution fence unapplied while still satisfying those assignment assertions. The existing live-execution tests use Replace and would not execute either regression.
- **Consequence:** The newly introduced large-membership removal path could stop unrelated running work, or omit the required immediate durable fence for removed work, without the checked regressions failing.
- **Suggested test shape:** Extend the existing guarded real-Task revocation helper with unchanged roles/expiry and explicit Remove mode. Create claims and delegations in one selected and one preserved engagement; assert affected epoch/state/claim/delegation changes and exact preservation of the other scope, then regrant the removed assignment and assert its old basis remains fenced.
