01

What an adapter Run now does

  1. Initiate An auditor names a Procedure and a date period. The platform walks the activated succession chain to find which version owns that period — not by version number and not by approval time, because neither expresses succession — and refuses if the lineage is broken or forked.
  2. Acquire the population A worker claims the Run under a lease and reconciles the source against a declaration generated independently of the data. The bytes and that declaration are hashed as a pair before the object is written, so a resumed attempt verifies the pair it already promised.
  3. Freeze the Reference Sources Each versioned file is acquired once, before any Work Item runs, and every rule that later consults it reads those frozen bytes rather than a fresh fetch.
  4. Extract Each API system becomes one Work Item, using a credential that has nowhere to live: the resolved object holds a reference and a method that sets a header, and no field holding a value. A web or desktop system is refused by name rather than skipped — skipping would let a Run conclude about a system nothing read.
  5. Register the Observations One transactional contract for every producer. Rows, check outcomes, corroboration, evaluations, the audit event and the notification commit together or not at all. A record the system does not carry counts as an honest absence only if the adapter derived a query key, stored the empty result as Evidence, and completed its extraction.
  6. Corroborate The stage that froze the artifact re-reads it, comparing as canonical bytes so three spellings of one number stay three different things. “Nothing could read it” and “it read differently” are recorded as different words.
  7. Evaluate The version’s compiled conditions are applied with no free-text rationale, because a rationale is where retrieved content gets quoted back as the reason for an outcome. Money compares on scaled integers.
  8. Gate, seal and publish Every Gate row is decided when the last Work Item completes, and the outcome table applies in order with the first match winning. Evidence falling short is Inconclusive; execution failing is Run Failed.
02

The central invariant, and where it actually lives

An uninspected, excluded, ambiguous or contradicted record is never Compliant.

That sentence is not a rule a command has to remember. It is a composite foreign key. An evaluation row carries the coverage state and corroboration verdict of the Observation it belongs to, held to that Observation’s own values by a key over the three columns together, under a constraint forbidding a Compliant value beside a contradicted corroboration. Claiming the right coverage in the evaluation row does not help: the pair has to exist in the Observation.

No command, no migration and no database session can route around it. The command refuses first, so a caller gets a named refusal rather than a constraint violation — but the constraint is what makes the guarantee true rather than intended.

Two independent adversarial reviews tried to find a path around it and could not.

Ten more, found after I called it done

Marking the pull request ready for review triggered an automated review, which posted ten findings. All ten were real. Four of them contradicted an invariant this project's own decision log already states in words — which is the strongest possible signal a finding is genuine: the rule was written down correctly and implemented incompletely.

  • A bucket outage was recorded as tampering. The missing-object check counted NoSuchBucket, so a deleted or misconfigured bucket made every read return nothing — which the verifier reads as a genuinely absent artifact. One outage would have written a permanent integrity finding, and its immutable event, against every artifact of every finished Run. S3 answers NoSuchBucket with HTTP 404, so removing the name alone would not have fixed it.
  • A fully covered Run could seal Inconclusive. The coverage read was capped at 100,000 rows, but the matrix is records × systems — and every dropped covered cell read as missing coverage.
  • Runs could queue with nothing to run them, and Runs could strand mid-flight with their Evidence already frozen. Both are the direct cost of an earlier repair on this same pull request: letting the worker start without object storage was right, leaving the work that depends on it startable was not.
  • A Gate total that had to be exact was the length of a truncated read, and a bad list cursor rendered an empty page instead of the first — its test asserted the defect, three lines under a comment saying the opposite.

Two findings touched decisions recorded as deliberate. Both decisions survive; the narrower defect underneath each is fixed. A Run that outruns a cancellation still concludes on its own merits — but the request is no longer answered by silence, which is what it was. And deleting a whole Run is still allowed, while deleting one Evidence row out from under its sealed package is not.

I swept for more instances of the same patterns and found none. The lesson is in the decision log in its own words: a rule stated correctly in prose and implemented incompletely.

04

Decisions taken, and why

These are the calls a reader would otherwise have to reconstruct from the diff. Every one is recorded beside the code it governs.

  • A Gate row’s failure outcome belongs to its diagnostic, not its row. The contract gives two rows both possible outcomes, so a table keyed by row loses half of it. One failure genuinely lands on two rows, and the contract says so twice.
  • Per-record coverage is per Template, and is now machine-readable. The four Template rules genuinely differ — one accepts a proven absence, another needs the account to appear with a grounded role list. That rule was prose, so the permissive reading was applied to all four, and an account whose permissions nothing could read passed its own control. It now fails closed to the strict reading, which can only degrade coverage.
  • An unaccounted population row is decided at the Gate, not at acquisition. Exactly one check moved. The outcome is unchanged — only when it is decided, and what exists by then. Every other check still stops the Run where it did, because those ask whether the bytes are what they claim.
  • An Evidence artifact frozen before it is parsed is named with its attempt. Otherwise a retry uploads different bytes to the first attempt’s key, the store refuses them, and every retry dies accusing storage of an integrity failure against a system that is answering correctly.
  • A refusal is thrown from inside a unit of work, never returned. A returned refusal commits everything written before it. The oldest rule in this codebase, and it still applies to every command added here.
  • Canceled is never produced by a timeout or a limit. That state is reserved for a person cancelling. A timeout that wrote it would put a sentence naming an actor on a Run nobody touched.
05

What is deferred, and named

Nothing here is hidden. Each item is named in the code or a story specification as well.

  • The desktop Target System and its execution port, deferred since Epic 1. The desktop path is exercised with a registered synthetic desktop rather than a real one.
  • The token limit mapping is implemented and unit-tested but never exercised, because nothing in this epic calls a model. It is wired so the agent epic fills it, rather than adding a limit that was never mapped.
  • Two Gate rows are transcribed backstops. They can only fail from a Session Step failure that already stops the Run before the Gate runs. They are tested in the domain.
  • A residual storage race. Object immutability rests on a read before write plus a conditional header. Two writers landing between one’s read and its write, on a backend that ignores the header, is still possible. Written down rather than claimed away.
06

How this was built and checked

Each story was specified before it was built, implemented by a separate agent against that specification, then verified independently against a real database before it was committed. Where a fix mattered it was mutation-proven: the fix was inverted, the test was watched failing, and the fix restored. A test that has never failed is not a test.

Two interruptions are worth recording rather than hiding. Three background agents were killed at once by a session rate limit; one had already written its work, which was picked up and verified rather than redone. Separately, two mistakes of mine cost time: editing the verification script while it was running, which corrupted that run, and killing a browser suite so its cleanup never ran, which left a row that failed an unrelated test afterwards. Both are now in the project’s decision log, and the verification script no longer exits successfully over a failing step.

Whether the epic is actually done

Yes — against a bar that was corrected once during the work. The brief assumed eight demonstrable terminal outcomes. Six are demonstrable in this epic and two are not, and the two are named rather than counted.

Both unreachable rows are implemented, sit in the contract’s order, and are tested with constructed state. They are not skipped; they simply cannot be produced by anything this epic builds.

Why the golden populations could not show success. They seed every failure mode at once — one lists an account twice, the other has a transaction with no processed time — and two Gate checks deliberately read the source rather than the included set, because a duplicate that scoping filters out is still two rows claiming one identity. No inclusion rule escapes them. That is the datasets working correctly, and it is why a clean source had to be built.

What “proven” means here. The real worker process, the real synthetic service over the network, real PostgreSQL and a real object store. Every assertion reads what the Run actually stored and compares it with an expectation file written by hand before any Run existed. The Pass and Control Failure populations differ by one role on one account, and two further accounts sit one permission short of a prohibited pair, so the rule’s boundary is tested rather than avoided. The fixture was mutated to confirm it can fail.

One gap is recorded rather than closed. No browser journey cancels a Run that has already acquired Evidence; that seam is proven against the database rather than through the worker process.
